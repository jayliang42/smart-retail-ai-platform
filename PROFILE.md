# Learning Profile

## Target

Transition from a product- and business-oriented Technical PM into a product-minded Technical IC who can independently build, test, deploy, and explain production-oriented AI systems.

Target roles:

- AI Engineer / Applied AI Engineer
- Data Engineer
- Backend / Platform Engineer
- IoT / Edge Engineer
- Product Engineer

## Existing strengths

- Retail technology and store-operation context
- IoT and enterprise software exposure
- Customer-scenario and product judgment
- Ability to connect technical work to operational value

## Evidence-based skill baseline

The repository now contains an AI-assisted working backend slice. This proves that the learning environment and project architecture are viable, but it does not yet prove independent skill. Personal levels remain pending until the learner explains and modifies the code.

| Area | Current evidence | Status |
|---|---|---|
| Python | Typed domain and repository code exists; quality gates pass | Explanation/change pending |
| SQL / PostgreSQL | Inventory/device/analytics repositories, JSONB results, migrations, constraints, and verified records exist | Query exercise pending |
| HTTP / API | FastAPI inventory/device/event slice, role-protected writes, actor audit query, and API tests exist | Learner-owned endpoint change pending |
| Data engineering | Versioned dataset, quality pipeline, immutable analytics runs, PostgreSQL result tables, and bounded query APIs exist | Learner explanation/change pending |
| Applied AI | Versioned RAG sources, pgvector retrieval, strict cited answers, typed tools, bounded Agent loop, approvals, and 60-case component evaluation exist | Implementation is AI-assisted; live-model experiment and learner explanation pending |
| Cloud / deployment | Non-root Docker image, Docker Compose, GitHub Actions, and Render blueprint verified locally | External cloud deployment requires account authorization; learner walkthrough pending |
| System design | Repository boundary, migrations, event/idempotency, atomic actor audit, RAG evidence, risk gateway, approval state, retry, and observability decisions recorded | Technical defense pending |
| IoT / Edge | Device registry and HTTP event-ingestion path exist | MQTT/edge baseline pending |

## Learning allocation

- 40% Applied AI, LLM, RAG, agents, and evaluation
- 35% Python, SQL, backend, APIs, and data
- 15% cloud, Docker, deployment, and observability
- 10% IoT, Edge AI, and foundational C++

## Working principles

- Produce runnable projects and GitHub evidence.
- Spend roughly 80% of training time coding and 20% on concepts.
- Attempt tasks before receiving full solutions.
- Add tests in proportion to risk.
- Evaluate AI behavior with datasets and metrics.
- Reassess difficulty from demonstrated performance, not calendar progress alone.

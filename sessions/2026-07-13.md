## Objective

## Timebox

## Core concept

A domain model represents business facts and enforces invariants close to the data. For an inventory adjustment, invalid quantities or missing identifiers should be rejected before persistence or API processing.

## Your coding task

Create `projects/smart-retail-platform/src/smart_retail/domain/inventory.py` with:

- an immutable `InventoryAdjustment` dataclass;
- fields `store_id: str`, `sku: str`, `quantity_delta: int`, and `reason: str`;
- validation that rejects blank identifiers/reasons and rejects `quantity_delta == 0`;
- a method that applies the delta to a non-negative current quantity and rejects a negative result.

Then create focused tests in `projects/smart-retail-platform/tests/test_inventory.py` using the standard-library `unittest` module.

Do not add FastAPI, PostgreSQL, or an LLM yet.

## Completion criteria

- The valid case returns the correct new quantity.
- Blank `store_id`, `sku`, and `reason` cases are tested.
- A zero delta is tested.
- An adjustment producing negative inventory is tested.
- `python3 -m unittest discover -s tests -v` passes from the project directory.
- You can explain why validation belongs in the domain model and name one limitation of this simplified model.
